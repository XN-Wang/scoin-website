## 1. 项目概述

### 1.1 项目背景
香港稳定币控股公司作为香港持牌稳定币发行人，需要建设面向公众的官方网站，用于品牌展示、信息披露、客户服务和合规要求。

### 1.2 目标用户
- **主要用户：** 机构客户（保险/再保险、光伏贸易企业等）
- **次要用户：** 监管机构（金管局等）
- **潜在用户：** 未来可能开放的零售客户
- **一般公众：** 了解公司和产品的访客

### 1.3 核心目标
- 品牌展示与信任建立（强调稳健、合规、服务）
- 满足监管要求的信息披露（透明度）
- 提供客户服务入口（投诉、登录、注册）
- 吸引潜在合作伙伴

---

## 2. 整体技术要求

### 2.1 响应式设计
- 必须支持桌面端和移动端访问
- 适配主流浏览器（Chrome, Safari, Firefox, Edge）

### 2.2 多语言支持
- **必须支持：** 繁体中文、英文
- 语言切换按钮位于页面右上角

### 2.3 性能要求
- 首页加载时间 < 3秒
- 图片需优化压缩
- 支持HTTPS安全访问

### 2.4 技术栈
- 由团队决定（建议：React/Vue + Node.js后端）

### 3.4 信息披露页面（重点）

#### 3.4.1 页面结构
参考Circle Transparency页面，包含以下Tab：
- **储备资产（Reserves）**
- **发行量与流通量（Issuance & Circulation）**
- **审计报告（Audit Reports）**
- **白皮书（Whitepaper）**

#### 3.4.2 储备资产Tab
**功能说明：** 展示储备资产的实时数据和组成

**显示内容：**
- 币种切换按钮：Scoin-HK | Scoin-US
- **数据更新时间：** "截至 YYYY-MM-DD 24:00"
- **关键数据卡片：**
  - 发行总量（Total Issued）
  - 储备资产总额（Total Reserves）
  - 储备资产构成（Reserves Composition）
    - 银行存款比例
    - 其他合格资产比例
    - （饼图或柱状图展示）

**数据来源：**
- 储备资产数据：需要手动上传/更新（后台管理功能）
- 更新频率：每日24:00自动更新
- **⚠️ 待确认：** 数据格式和更新机制

**设计参考：** Circle的Reserves composition页面

#### 3.4.3 发行量与流通量Tab
**功能说明：** 展示稳定币的发行量和流通量数据

**显示内容：**
- 币种切换按钮：Scoin-HK | Scoin-US
- **数据更新时间：** "截至 YYYY-MM-DD 24:00"
- **关键数据：**
  - 总发行量（Total Issued）
  - 当前流通量（In Circulation）
  - 7日变化量（7 Day Change）

## 6. 数据接口和API需求

### 6.1 需要提供的API接口

#### 6.1.1 发行量/流通量数据API
- **功能：** 获取Scoin-HK和Scoin-US的发行量和流通量数据
- **调用频率：** 每日24:00自动调用
- **⚠️ 待确认：**
  - API端点URL
  - 请求方法（GET/POST）
  - 返回数据格式（JSON示例）
  - 鉴权方式
  - 错误处理机制

**建议返回字段：**
```json
{
  "coinType": "SCOIN_HK", // 或 SCOIN_US
  "updateTime": "2026-01-29T24:00:00Z",
  "totalIssued": "1000000000.00",
  "inCirculation": "950000000.00",
  "change7d": "-5000000.00",
  "change30d": "+20000000.00"
}
```

#### 6.1.2 客户投诉提交API
- **功能：** 将官网投诉表单数据提交到运营平台
- **⚠️ 待确认：**
  - API端点URL
  - 请求方法（POST）
  - 请求数据格式
  - 投诉单号生成规则
  - 成功/失败返回码
  - 是否支持附件上传

**建议请求格式：**
```json
{
  "complaintId": "自动生成", // 或由API返回
  "name": "投诉人姓名",
  "phone": "联系电话",
  "email": "联系邮箱",
  "type": "服务质量",
  "details": "投诉详情",
  "attachment": "附件URL或base64",
  "submitTime": "2026-01-29T10:00:00Z"
}
```
